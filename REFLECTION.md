# HW4 Reflection

The part I repeated most often was the shared page shell. Every page needed the same header, logo, site name, main navigation, and footer. I also repeated the required head information: the doctype, language, character set, viewport, unique title, description, and links to the shared style sheets. The nested `guide` directory made the repetition more noticeable because every path had to change from `styles/...` and `images/...` to `../styles/...` and `../images/...`. A missed pair of dots could break an image, style sheet, or navigation link.

The four family pages created another repeated pattern. Each page used the same grid layout, navigation, hero image position, section order, and previous/next navigation. Only the title, image, text, metadata, and neighboring links changed. I also repeated family information on the guide page: a heading, illustration, summary, link, image dimensions, alternative text, and view-transition name. The structure was consistent enough that writing each page manually felt more like filling a template than designing a new document.

I would want a tool to generate the shared shell from one source while still producing complete static HTML files. The tool should understand the current page’s directory depth and create correct relative paths automatically. It should also mark the correct navigation link with `aria-current="page"`, generate unique titles and descriptions, and preserve semantic elements instead of replacing everything with generic containers.

For the family pages, I would want one data file containing each family’s name, image, description, sections, and order. A generator could use that data to create the guide listings, all four detail pages, previous/next links, alternative text, and matching view-transition names. Reusable web components could eventually handle the visible header and family card, while a static-site generator would be better for producing the repeated files without requiring JavaScript in the delivered site. I would still want the generated HTML and CSS to remain small, readable, and easy to edit by hand.
